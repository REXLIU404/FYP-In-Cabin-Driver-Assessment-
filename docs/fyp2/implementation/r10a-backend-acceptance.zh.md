# R10-A 验收报告（中文）：后端的观测身份、规范采集时间、NEW-only EMA 与双条件 FSM

## 1. 任务概要

- **编号与名称**：R10-A，R10 的后端部分。你在 10-16 批准了 v3：第 5 条采用 estp5，另附 3 个细节。
- **实现了什么**：
  - **观测身份**：遥测按 `(session, telemetry_seq)`，视觉按 `(session, epoch, presentedFrames)`。没有身份字段时回退：遥测用时间戳加特征哈希，视觉用图像哈希。图像哈希只做审计，不会把新帧改判为重复。
  - **规范采集时间**：每个身份第一次被接受时登记采集时间，重复观测（REPEAT）永不刷新它。年龄按未舍入的精确值计算并比较（细节 1）。REPEAT 使用登记时保存的概率和特征，不用这次重新推理的结果。
  - **冲突与乱序**：同一身份带着不同的内容或时间，返回 409 `observation_conflict`（新的故障类别，不可重试）。显式身份只能单调前进，回退时返回 409，沿用乱序 detail，Task 8 的客户端会丢弃该帧。
  - **NEW-only EMA**：只有新视觉观测会更新平滑值；REPEAT 不延长链；链因缺失、过期、不可用或 gap 断开后，不会被旧的 REPEAT 接回去。
  - **双条件 FSM**：只作用于 Live 模式，PREPARED 模式逐窗口保持旧行为。升级（或恢复）必须同时满足：
    - 服务端时间达到阈值；
    - 新的同向观测在来源时间上覆盖了阈值。首个窗口的跨度为 0；之后只有新观测能推进跨度；跨度达标后，墙钟条件可以由随后任何窗口满足。
  - **完成守卫（细节 2，按意图实施）**：最后一次推进跨度的那一路，在触发转移的窗口里必须仍然有效，并且仍在支撑一侧。
  - **支撑判定**用会话阈值。
  - **request hash 兼容**：新字段为 None 时不参与 hash，升级前发出的请求在升级后重试仍是幂等重放。
  - **UT-TIME-05** 从「已知限制」改为需求断言：同一证据在 3 s 内被重复提交，不再累积到 HIGH_ALERT。
- **为什么必要**：P0-D13 之后仍有三个缺口，Codex 的独立评审也确认了它们：
  - 有效期 3 s 比升级阈值 2 s 长，所以同一观测在过期前被反复提交，就能累积到 HIGH_ALERT；
  - 重复的视觉输入会反复更新 EMA，分数会随请求频率变化；
  - 同一观测换一个新时间戳再交，就能「续命」。

## 4. 问题与风险

- **失败测试**：无。**非预期回归**：无。
- **细节 2 按意图实施**：字面写法是「任一路在支撑一侧」，在你描述的情形下，模拟器在 2.5 s 放行了升级。意图版能挡住这一情形，在其余既有场景上与字面版一致。V9 证明测试能区分两者。
- **已知限制，都已写进测试或报告**：
  - **K2**：来源时间戳带抖动时（例如两个样本相隔 1975 ms），告警会延迟一个样本。测试按此断言，不写死「第二个样本必定触发」（细节 3）。
  - **混用身份**：同一会话里混用显式身份和回退身份后，原样重发最后一个显式身份会被拒绝（409），而不是判为 REPEAT。这是保守的结果，R10-B 的客户端总是带显式身份，不会触发。已用测试钉住。
  - **显式身份的新观测不受时间水位线约束**：客户端时钟回拨时，这类观测仍判 NEW，但会按其规范采集时间过期。
  - **REPEAT 仍会跑一次模型**，结果被丢弃，改用登记时的概率。这是性能代价，不影响正确性。
  - **非 0.5 / 0.5 权重时**，单分支分数与融合分数的浮点计算路径不同，在恰好 .x5 的平局处，窗口可能被视为「无支撑」，结果偏保守。
- **R10-B 必须遵守的后端约束**：
  - 摄像头关闭时不能发送 `vision_frame`；
  - 遥测缺失时不能发送 `telemetry_seq`；
  - 违反任何一条都会返回 422，422 不可重试，会话会因此停下。
- **外观问题**：`44b7c62` 和 `ef341fa` 的提交信息多了一行 Sonnet 署名（子代理按自身环境写入）。最后一行仍是规定的 Opus 行，提交禁止 amend，所以保留原样。
- **工作树清理**：删除了一个 10-12 遗留的、指向主仓库的多余符号链接 `node_modules 2`，只删了链接本身。
