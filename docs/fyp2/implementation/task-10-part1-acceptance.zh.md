# Task 10 第 1 部分验收报告（中文）：测试基础设施、导出守卫、计时与门禁日志

## 1. 任务概要

- **编号与名称**：Task 10 第 1 部分。Task 10 拆成两部分：本部分只做不依赖 R10 的基础设施；端到端测试等 R10 落地后，放在第 2 部分做。
- **实现了什么**：
  - **P1 类型检查门禁**：新增 `npm run typecheck`；`npm test` 先跑类型检查，再跑 vitest，类型错误会让 vitest 根本不启动。另加一条守卫：仓库里不能出现会被 vitest 静默跳过的 `*.test.tsx` 文件。
  - **P2 模型跳过显式化**：pytest 汇总里会醒目地列出因模型文件缺失而没跑的测试。设置 `DRA_REQUIRE_MODELS=1` 后，这些跳过一律判为失败。
  - **P3 导出守卫（R31）**：历史行的 payload 为 NULL、不是合法 JSON、不是对象，或者是无法按 UTF-8 解码的二进制时，导出不再在开始输出之后才报错。这类行导出为一条带 `payload_unreadable` 标记和原因的最小记录：不丢行，也不伪造风险字段。可读的行，JSON 导出与改动前逐字节相同；CSV 的表头和每一行末尾多了两列（标记与原因），可读行的这两列为空。
  - **P4 `freeze_manifest.py` 严格化**：设置了 `FYP_DATA_ROOT` 但目录无效时，脚本报错并以非零退出码结束，不再悄悄改用其他路径。
  - **P5 分段计时**：
    - 后端 `/infer` 的响应带 `Server-Timing` 头，包含 preprocess、vision、telemetry、fusion、commit、total 几段，commit 段在 `db.commit()` 之后计时。
    - 前端为每个窗口记录三段：截帧到发出、网络往返、收到响应到渲染。这些数据存在一个有上限的环形缓冲里，供第 2 部分的端到端测试读取。
    - 本部分**不**给出任何性能结论。
  - **P6 门禁原始日志**：新增 `scripts/run_gates.py`。每一道门禁都记录 argv、工作目录、环境变量、工具版本、退出码、完整输出和 skip 数，最后生成 `SUMMARY.md`。任何一道门禁失败，脚本就以非零退出码结束。
- **为什么必要**：Codex 审阅 R02、R17、R31 指出了三个问题。
  - 门禁证据没有原始日志。
  - 模型缺失时，测试会静默跳过，pytest 仍然报绿。
  - 导出遇到坏的历史行时，客户端会拿到半截文件。
  - 另外，「端到端延迟 ≤ 1 s」目前没有可测量的分段计时支撑。

- **失败测试**：无。**非预期回归**：无。
