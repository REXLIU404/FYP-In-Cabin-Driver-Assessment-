# Task 8 验收报告（中文）：有界重试、冻结 payload、可见的停止状态

## 1. 任务概要

- **编号与名称**：Task 8，有界重试、冻结 payload、可见停止状态（D02 Option 1），含 R5「摄像头停止后循环继续」与 R7 裁定。
- **实现了什么**：
  - 推理循环从 React hook 中抽出，成为纯模块 `ai/src/liveLoop.ts`，所有依赖都注入，可在 node 环境下用假定时器测试。失败分类与退避抽到 `frontend/src/api/retryPolicy.ts`。
  - **有界重试**：一个请求最多投递 3 次（首发 1 次加自动重试 2 次），退避 2 s 和 4 s。3 次都失败就停止，不再排任何定时器。
  - **冻结 payload**：同一请求每次重试都逐字节重发同一份内容，`request_id`、图像、时间戳、遥测都不变。每次投递都带 `X-Attempt-Index`（1、2、3），手动重试接着往上数（4、5 …）。
  - **可见的停止状态**：停止面板显示类别、request id、投递次数（例如「1 of 3 + 1 manual」），并说明 Retry 是恢复同一会话还是新建会话。Retry 调用 `live.retry()`，不会悄悄换会话。
  - **分类**（R7）：
    - 503 → `models_unavailable`，不可重试；
    - 500 → `model_runtime`，可重试；
    - 新增 `conflict_mode` 和 `clock_skew`（时钟超前，带专门文案）；
    - **到达顺序错乱的帧（409）直接丢弃，不计数，不停止**，以前它会让会话永久停住；
    - hash 冲突的 409 仍立即停止；
    - 用户暂停引起的中断不计为失败，超时与暂停可以区分。
  - **R5**：摄像头停止（`captureFrame` 返回 null）时照常发请求，不计失败，不停止。图像和遥测都为空时也照发，得到一条 UNAVAILABLE 窗口。主动 Stop Camera 与摄像头意外断开带不同的原因码，只用于显示，不计入失败次数。
  - **后端测试**：
    - IT-RETRY-IDENTITY：提交成功后响应丢失，用同一 UUID 重发，DB 恰好一行，时序状态只推进一次；同一 UUID 改内容则返回 409。
    - IT-RETRY-STALE：钉住**现行**行为，采集后 6 s 才处理的重发是 stale / DEGRADED。
- **跟进修复**（`90a2f2f`）：
  - 「New Session」建会话失败后点 Retry，原来会悄悄回到旧会话，这是真缺陷，现已改为新建会话；
  - 补上 500 类别的断言、15 s 期限下界的断言；
  - 修正投递次数的显示。
- **为什么必要**：D02 要求「连续 3 次失败后停止、手动重试、不产生重复记录」。修复前的情况：
  - 每次重试都生成新 UUID、新帧、新时间戳，服务端已提交的请求在超时后重发，会写出重复记录；
  - 失败计数藏在闭包里，界面看不到；
  - 一个迟到的帧会永久停掉会话。
